# Alpha 4 后续：桌面集成与首次运行

状态：进行中。本文是验收清单，不代表功能已经完成。

## 交付顺序

1. Windows 输入设备：修正 digitizer 位标志；Raw Input 枚举键盘，失败不能写成 false。
2. 窗口：保留现有绘制区尺寸，外扩宿主；合成抗锯齿圆角与自绘阴影；启动/关闭遮罩连续收至图标后方。不得以全透明主窗口牺牲 DWM 动画。
3. 设置：重排全局设置列表；独立实例设置使用既有分层设置服务，明确继承与覆盖。
4. 文件交互：版本行双击打开目录；系统拖放保留 Ctrl/Shift/Alt 语义；导入先识别再确认，不能将未知文件直接执行。目录识别 Minecraft 根目录/实例，JAR 提供模组/核心/加载器选择，MRPACK/ZIP 交由整合包服务。
5. 任务泡泡：每个泡泡均有横向展开信息，隐藏项不占位置，动作和导航一致。
6. JVM：核对现有 IJvmHost 与独立 Jvm.Host 的职责；验证实际 Minecraft 启动、日志、退出、崩溃、取消与多实例隔离。
7. 首次运行：欢迎 → 数据存储位置 → 用户体验计划与遥测 → 结束。正式版遥测默认关闭、可撤回；CI/Alpha/Beta 明示并强制启用基本数据收集；异常记录必须脱敏。
8. Cloudflare：在现有上级 Server Worker 中接入遥测 API，并连接已有更新流；完整验证签名、通道、平台与失败回退。
9. Patch：先确认 Java/C# 目标；冻结 HEAD/ARGS/TAIL/RETURN/REPLACE 的顺序、异常和返回语义，再实施生成器。不得把只能生成新代码的 source generator 宣称为任意现有方法重写器，不得使用 NativeAOT 不支持的运行时动态代码。

## 当前输入设备修正

Windows `SM_DIGITIZER` 的 READY 为 0x80，集成/外接触摸分别为
0x01/0x02，集成/外接笔分别为 0x04/0x08。MULTI_INPUT 本身不证明触摸存在。
键盘使用 `GetRawInputDeviceList` 的 RIM_TYPEKEYBOARD；枚举热插拔重试有界，
失败投影 TemporarilyUnavailable，不把 Windows 会话本身视为物理键盘。
形态推断复用同一探测；键盘未知时保守地不推断为无键盘掌机。

## 验收

每批独立提交并推送。涉及服务契约的批次补契约测试和架构检查；本机互操作
必须执行 NativeAOT 测试。视觉批次检查不同 DPI、最大化/还原、快速反向操作、
减弱动态效果。完成状态以真实验证结果为准。

## 泡泡呈现

任务、启动和进程泡泡共用 HoverExpand 横向弹簧呈现，静止为 48 DIP 图标圆，
展开向左且右侧锚点不动。任务展示数量、百分比和进度轨；进程展示实例名称与动作。
键盘焦点也可展开。纵向停靠仍按 48 DIP 高度排列，退出项立即释放位置。

## 关闭动画连续性

启动期间关闭以当前 mask 半径和图标缩放作为起点；取消旧图标轨道，避免两个图标叠加。
图标折叠同步收缩原生区域，最终为空区域；销毁前不得恢复完整窗口区域。
此项不等于完成抗锯齿或外扩阴影，后两项仍待合成层处理。

## 实例设置

版本设置复用 SettingsPolicy 的 Instance 层，完整实例目录为身份，禁止只以版本名索引。
页面仅显示支持实例覆盖的定义；恢复继承删除覆盖，不能写全局值。启动协调器由组合层
注入 SettingsPolicy，读取该实例快照并应用已接通的窗口尺寸、全屏和 JVM/游戏参数。
目录切换需丢弃旧异步读取与编辑草稿。

## 遥测协议

Nexa 2 更新发现与下载使用独立 `/v2/updates/`，旧版 `/v1/updates/` 保持原合同。
Cloudflare 从官方 GitHub 发布目录读取严格的 2.x dotted tag，区分 stable/beta/alpha 与六个 RID；
CI 默认跟随 Alpha 发布。安装包和便携包都存在时才提供更新。客户端经 sealed query 异步检查，
显式下载通过系统浏览器获取平台安装包，可直接打开 GitHub 发布说明。此阶段不自动执行安装包，
不宣称已有静默替换、增量升级或原子回滚；这些仍由后续签名安装事务接入。

`POST /v1/launcher/telemetry` 经现有 Cloudflare API Shield mTLS 验证。
只接受 app.started/app.failure/game.started/game.exited，字段限 version/os/arch/result
及事件时间；单批 50 条、16 KiB。Worker 严格拒绝额外字段，仅存每日聚合计数。
不保存设备 ID、IP、账户、路径或原始日志。传输失败保留队列，语义为至少一次，
不能用这些计数宣称精确独立用户数。正式版撤回同意清空待发队列并取消当前会话发送。
测试通道由 Services 的版本策略强制启用，OOBE 与设置均明确标示，不提供无效的关闭选项。
构建使用现有 PCLN_API_CLIENT_PFX_BASE64 secret，仅将证书恢复为忽略文件；不得记录证书内容。
首批客户端接入 app.started；游戏结果及异常事件仍需各自产生者接入。

## 首次运行引导

在 Foundation、账户、游戏扫描与联网会话初始化之前运行独立的轻量引导 shell。
欢迎 → 数据位置 → 用户体验计划 → 完成；关闭不提交，返回保留本次草稿。正式版遥测初始为关闭，测试版显示必需收集说明。
设置与账户已存在的安装直接沿用原目录。环境变量指定目录时保留最高优先级，并锁定目录选择。
Services 通过 sealed query/command 验证和保存；Desktop 仅维护页面草稿与调用系统选目录。
最终提交先写目标目录设置，再原子保存 LocalApplicationData/NexaCL/storage.json 位置记录；
提交失败回滚本次新建设置，不覆盖已有配置。完成后自动重新打开应用，所有服务从所选目录初始化。
游戏目录不随应用数据目录迁移。引导期间无遥测发送，主界面仍通过既有设置服务管理撤回同意。
验证包含返回保留草稿、默认关闭、退出不保存、环境变量锁定目录、旧安装跳过、已有文件保护、
位置记录失败回滚及重试。`--validate-setup` 无写盘地渲染四步页面，纳入 NativeAOT 与 trim CI。
默认位置允许启动检测预建的空 settings/profiles 目录；真实配置仍受保护，拒绝经设置目录链接写入。

## 版本行点击语义

鼠标单击延迟至双击判定窗口结束后选择并返回；Windows 使用系统双击间隔，其他平台暂用 500ms。
同一版本行在该间隔内再次点击打开实例目录，不改变选择、不退出页面。键盘激活立即选择。
离开页面、切换目录或执行其他操作取消待决单击。目录打开由 Host 执行，服务仍拥有选择状态。

## 本地文件夹拖入

Host 仅发送本地路径，Desktop 经 sealed query 读取识别结果，再经 command 执行。
识别和复制在后台运行，禁止在 DragOver 中扫描文件系统。游戏根目录通过现有 Library
服务注册；独立版本目录采用复制语义，保留源目录，拒绝覆盖、符号链接和递归导入。
版本在当前根目录的临时区完成复制与校验后原子移入 versions，再刷新目录列表。
导入前校验完整继承链：父清单可来自版本内文件或目标根目录；缺失、循环、越界即失败并明确
报告依赖，不将叶版本作为成功结果发布，也不隐式复制整个来源游戏目录。
复制纳入任务中心并支持取消。此阶段不宣称支持 Move/Link、拖出或整合包安装。

## 本地 JAR 用途与核心补丁

JAR 拖入读取归档内容，不按文件名推断加载器版本。用途由用户明确选择；模组写入捕获实例
实际使用的隔离/共享 mods 目录，拒绝覆盖。核心补丁只作用于拥有独立核心的版本，保留备份，
移除 META-INF 中的签名文件、保留服务声明，并拒绝越界路径。提交前核对拖入文件的 SHA-256，运行中的版本拒绝修改。
核心补丁摘要保存在实例 metadata，启动补全仅在摘要一致时保留该核心，不关闭其他文件校验。
运行状态携带规范化完整实例目录；JAR 修改以该目录比较身份，不以裸版本 ID 阻止其他根目录。
受支持的本地加载器安装器复用现有隔离安装流程；安装器在明确确认后才允许执行。

## MRPACK 与 CurseForge ZIP

任务中心在业务锁内给每次登记分配 generation、每次更新递增 revision，并同时入队。
唯一发布者在锁外按队列顺序更新列表及摘要；观察者重入只入队，不递归发布。
删除也属于同一队列，旧登记的删除不能越过后来复用同 TaskId 的登记。

归档限制同时约束声明长度与实际读取量。清单在有界缓冲中完成长度校验后才解析；覆盖文件
在写出前扣减共享事务预算，读到超出声明长度的第一个字节即失败。短读同样拒绝提交。
下载文件通过现有实际长度校验后计入事务预算，客户端覆盖不得重新获得独立预算。

按根清单识别，预览锁定 SHA-256、Minecraft/加载器版本及实例名称。客户端跳过 server-only
文件，可选文件由用户选择。MRPACK 校验 SHA-1、SHA-512 和长度；CurseForge 复用官方 API
与 MCIM 回退解析精确项目/文件，缺少授权 URL 时失败，不拼接绕过授权的地址。
复用安装与下载服务，在临时根完成依赖和覆盖文件后才发布隔离实例。禁止覆盖启动器 metadata、
版本清单或共享库；客户端覆盖最后应用。共享资源只添加或复用相同内容，禁止覆盖冲突文件。
失败可留下已验证的共享缓存，但不得发布目标实例。拒绝越界、链接、重复路径和大小越限。
CurseForge 文件按项目类型分别放入 mods、resourcepacks 或 shaderpacks；未知类型拒绝导入。

本批验证：Services 287 项（CoreCLR 与 Windows NativeAOT 原生程序均实际运行）、
Desktop 82 项、30 个项目架构检查。覆盖可选文件、客户端覆盖顺序、摘要失败、下载中取消、
共享库冲突、受保护文件、源归档变化和 CurseForge 下载限制；网络使用可重复的协议桩，
不将此结果表述为第三方在线整合包的端到端启动验证。
