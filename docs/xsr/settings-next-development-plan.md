# Nexa 2.x 设置与实例详情：下一轮开发计划

状态：阶段 1（S0）与阶段 2（S1）的设置基础已实现；其余阶段待开发。2026-09-12。

交付入口：[目录与继承契约](migrations/settings-catalog-and-inheritance.md)、[完整 IA 条目表](settings-entry-map.md)、[基础值契约表](settings-value-contracts.md)。566 个 IA 节点已保留最终位置；29 个基础值契约已声明。未来能力的设置仍显式保留为 reserved / NotImplemented，不伪造默认值或开启控件。当前阶段未实现设置页面，也未宣称新设置已接通所有运行消费者。

依据：用户提供的《Nexa 2.x 设置系统最终 IA.md》。本文将附件作为产品设计输入，整理实现顺序，不把附件中的未来能力视为已经存在，也不替代已锁定的 XSR 架构契约。

## 1. 本轮目标

先建立稳定的设置系统，再分批接通真实能力。一次确定最终导航和控件位置，不一次实现 Cloud、CAS、Overlay 等全部功能。

- 全局设置固定九页：通用、外观、游戏、Java、下载与网络、存储与迁移、N Cloud、隐私与诊断、更新与高级。
- 实例详情固定九页：概览、内容、世界、服务器、文件、截图、变化与恢复、诊断、设置。
- 实例设置固定十个 Section：基本、Java、资源与性能、窗口与启动、JVM 与 Hooks、启动配置、服务器、更新与安全、同步与备份、高级。它们是实例设置内部的分组，不再扩为一级导航。
- 修改版本保持独立页面，复用现有安装编辑器，不迁入实例设置。
- 普通未实现项目保持最终控件和位置，禁用并标注“尚未可用”；开发者项目仅在开启开发者选项后出现。
- 本轮所有启用的设置必须实际生效；仅有旧设置键或底层算法不算可用。

## 2. 已核实的起点

| 当前基础 | 本轮处理 |
|---|---|
| SettingsService、冻结 Schema、类型化 State、持久化成功后发布、稳定错误码 | 延用，不另建 Desktop 设置存储 |
| LauncherSettingsJsonPort 与旧键默认值、未知字段保留 | 延用，新增字段映射和迁移回归 |
| Foundation SettingsSet / SettingsGet 路由 | 扩展所需契约，页面经路由读写 |
| Java 扫描/安装、下载、启动与更新等 Service | 按实际消费者逐项接入，不用开关假装已有能力 |
| 已有版本修改编辑器、默认选项与差异安装计划 | 保持独立入口，与实例概览关联 |
| 实例设置仍使用 VersionSubpage；尚无完整最终设置页集合 | 建立专用页面和共享设置控件 |

XSR-501/503 的文档记录是迁移时的历史基线，不能将其中键数量直接当作当前功能完成度。

## 3. 开发顺序与交付件

### S0 — 设置目录与契约锁定

建立逐项可审查的映射表：页面、Section、稳定 ID、类型、默认值、单位/范围、作用域、旧键、拥有者、可用条件、生效时机、是否可导出。

- 区分可编辑设置、只读状态和操作按钮，避免将“扫描 Java”“打开目录”等注册为持久化布尔值。
- 分离 UI 目录元数据与值 Schema；一个旧值允许迁移到新产品名称，但不能因名称调整丢值。
- 为枚举、路径、数值范围、跨字段校验、实例覆盖声明明确契约。
- 可用性区分未实现、平台不支持、依赖缺失和暂时故障；不能全部伪装为“尚未可用”。
- 更新相关迁移说明后才扩展数据边界；沿用现有语义 ID、封存注册与 NativeAOT 约束。

验收：全部附件条目都有唯一归属；九/九/十结构有契约测试；重复入口指向同一值，不产生重复存储。

### S1 — 继承与持久化基础

由 Service 计算 `Builtin → Global → Instance → Profile → Temporary → Effective`，通过封存的 XSR State/Query 投影有效值、来源和校验结果。

- 本轮接通 Builtin、Global、Instance；Profile/Temporary 建模并测试优先级，未有实际能力时不开放编辑。
- “继承”表示该层没有覆盖，“自动”是明确策略，“自定义”保存值；禁止用 0、空字符串或 -1 混淆三者。
- 重置实例项仅移除该项覆盖；全局变化仅传播至继承项。记录重启生效、下次启动生效或立即生效。
- 保留 durable-first：写入失败不发布成功状态；滑块拖动使用临时预览，提交动作再持久化，避免逐帧同步落盘。
- 导入先校验和预览差异，再原子应用；不覆盖未识别数据，不把代理密码、令牌等混入普通导出。

验收：覆盖优先级、自动与继承差异、撤销覆盖、重启持久化、失败不变更、旧文件兼容均有测试；Desktop 不计算继承、不直接访问设置文件。

### S2 — 紧凑设置组件和全局九页

建立共享 Toggle、枚举选择、数字输入、可拖动滑块、路径行、操作行、继承编辑器、只读行和禁用状态。

- 窄且稳定的导航；页面直接显示内容，不增加 Hero、大标题空白或账户入口。
- 采用当前主页的颜色、字体、圆角与密度；分组小间距，说明只用于解释必要行为或风险。
- 控件状态切换保持焦点；只给展开/收起和结构变化加可中断动画。滚动不重复播放入场动画。
- 键盘、屏幕阅读器、减少动态效果、小窗口和长文案均纳入验收。
- 开发者选项只增加当前页面的 Developer Section，不改变普通设置位置或另起模式体系。

验收：九页可完整浏览，禁用控件不会发写入命令；滚动、下拉定位、焦点、滑块拖动和快速导航不抖动、不阻塞 UI。

### S3 — 接通已有能力，按消费者分块交付

优先顺序：Java → 游戏默认策略 → 下载与网络 → 通用/外观 → 隐私与诊断/更新。

1. Java：复用运行时扫描、验证与安装服务，接通默认策略、首选项和列表；删除只允许托管 Runtime，外部 Runtime 不删除文件。
2. 游戏：先接内存、窗口、隔离、已有 JVM/Game 参数和启动后行为。每个设置验证实际 Launch Plan 或运行行为；未支持的 Hooks/平台能力保持禁用。
3. 下载：接来源策略、并发/限速/重试中已具备的消费者；明确仅影响新任务还是可影响进行中任务。不能只写入未被读取的旧键。
4. 通用/外观：优先现有动画、窗口和主题消费者；系统集成按平台能力开放。
5. 隐私与诊断/更新：接日志、现有诊断和更新查询；签名、回滚等逐项核验完整执行链后启用。

验收：每个启用控件均有“设置 → 持久化 → 重启读取 → 真实消费者”的验证；不可用项目仍在最终位置。

### S4 — 实例详情九页与实例设置十组

- 实例概览读取现有元数据，接启动、修改版本和打开目录。
- 实例设置优先接名称/图标、Java、内存、窗口、启动参数与隔离，复用 S1/S2 的模型和控件。
- 内容、世界、服务器、文件、截图等先按最终结构呈现；仅接已有完整查询或操作能力，未来项目保留具体禁用控件。
- 从主页或版本列表进入实例设置，返回路径和左上角标题保持一致；切换实例不得残留上一实例的值。
- 全局变更不能覆盖自定义实例值；实例编辑不得改变 Minecraft 本体版本，版本组件修改仍进入独立编辑器。

验收：全局继承/实例覆盖/恢复继承能反映至真实启动计划；独立实例不串值；导航、返回与标题一致。

### S5 — 集成与发布检查

- 补齐 Service 契约、Desktop 交互与架构回归。
- 执行 dotnet format 和格式复查，按独立交付件提交推送。
- 最新提交 XSR CI 完整绿色，确认 NativeAOT Desktop shell smoke 和 trimmed Desktop smoke 实际执行且成功，不以跳过代替通过。
- 对可用设置做目标平台人工交互验收；shell smoke 不代替真实视觉和平台行为验证。

## 4. 本轮边界与后续能力

本轮完成最终结构、设置基础和现有能力的真实闭环。以下作为后续独立能力包，不混入设置 UI 的实现提交：

- Change Journal / Snapshot / Restore：先定义修改记录、失败恢复和存储语义，再接版本修改及内容更新。
- Preflight / Repair Plan / Resource Estimator：以 Service 输出和可解释结果为前提。
- CAS / 去重 / Hardlink-Reflink / CoW：先完成存储一致性与平台边界。
- Profile / Temporary Overlay / Safe Launch：先完成覆盖生命周期及恢复策略。
- N Cloud：同步、冲突、设备、备份分别闭环，不因 IA 保留位置而默认已有服务。
- World Guardian、系统关联诊断、AI 修复：依赖数据与执行边界完成后再开放。
- 联机和插件遵循既有 Sidecar 路线，本轮不加入全局设置导航。

## 5. 附件中需要统一的语义

- 更新通道：附件的 Stable/Beta/Preview-Nightly 是显示分组建议；不能替代当前 `stable/alpha/beta/ci` 产品版本契约。必须覆盖正在使用的 Alpha，并明确分组映射后再接更新筛选。
- 窗口标题：“基本”和“窗口与启动”两处入口共用同一个覆盖值；后者是完整编辑入口，基本页可显示摘要/跳转，不建立第二份设置。
- 默认服务器：“服务器”详情负责列表与环境，实例设置负责启动默认目标；两者使用同一服务器标识。
- N Cloud 的 Cloud Account 是同步状态，不将 Minecraft 账户管理搬入设置。
- AI 诊断配置与实验性 AI 修复开关分开：前者配置诊断能力，后者只决定实验修复功能是否开放。
- Developer Options 控制展示，不等于权限授予，也不绕过服务校验。

## 6. 本轮完成标准

用户能在固定位置找到设置，区分“继承”“自动”“自定义”，修改已开放项后确实生效；未开放项明确禁用。设置失败不会伪装成功，UI 不承担业务策略，实例修改不丢配置，后续能力接入无需重新排列导航。
