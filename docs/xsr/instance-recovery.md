## 成功条件

## 恢复命令接入约定

`minecraft.instance.recovery.restore` 接收完整实例目录、基线 revision、差异指纹和明确的条目集合。
文件条目另外携带 area，避免共享目录与实例目录中的同名路径混淆。服务在根目录独占租约中
重新比较并验证全部选择；过期预览、重复条目、活动游戏或未处理事务均拒绝。UI 不构造文件路径。
恢复命令仅操作已选择的更改；空集合拒绝，不解释为恢复全部。执行失败保留持久补偿记录。

进程创建不等于游戏成功启动。记录本次会话的窗口确认事实；只有明确确认启动、
退出码 0、生命周期为 Exited、未取消/强制结束、没有本次崩溃证据时才允许提交基线。
Unsupported / TimedOut 的窗口探测不可伪装成确认成功；需补充可验证的游戏内就绪
信号才可在无窗口探测平台建立基线。正常退出之前不覆盖旧基线。

## 快照范围与存储

- 按完整实例目录区分身份，同时记录实际 GameDirectory；共享与隔离目录不可混用。
- 纳入当前版本清单、核心补丁 JAR、启用/禁用模组、config、options 及启动设置。
  原版可重新取得的公共 assets/libraries 不重复备份。继承版本所需清单/核心的恢复
  需显式记录依赖，不能只恢复叶清单后宣称可启动。
- 存档、截图、日志不参与回滚。差异页明确说明恢复范围，不删除游戏进度。
- 文件计划包括 mods、config、defaultconfigs、scripts、kubejs、resourcepacks、shaderpacks、
  顶层 options*.txt、实例清单/核心 JAR 和 Nexa/InstanceMetadata.json。依赖文件使用
  root 区域，仅允许 versions/<目录>/<文件>.json 或 .jar；不能通过该区域恢复任意根文件。
  枚举设条目/深度预算，清单解析设实际读取预算；缺失父清单、循环或越界均拒绝建立基线。
- 内容按 SHA-256 寻址去重；可压缩内容压缩存储；每次基线只保存文件路径、摘要、
  大小和必要的设置元数据。保留最后成功基线与正在进行的恢复事务所引用对象，安全
  清理不再引用的对象。JAR 已压缩，不能承诺压缩率；首次恢复需要保留不可重新取得的数据。
  不用指向可变原文件的硬链接冒充备份。快照对象和配置正文只保存在本地，不上传遥测。
- 所有扫描/复制在 Services 后台运行，实际字节与条目数有预算；拒绝链接越界，文件
  在读取时变化则不提交。空间不足、取消或校验失败保留旧完整基线，不发布残缺快照。
- 同一游戏根目录的后台基线采集与启动/安装/改名/模组启停协作互斥。普通操作彼此
  保持原有并发语义；若基线正在复制，新操作先取消采集并等待其退出，再继续。
  采集只能在没有这些操作时进入，不排队抢占用户操作。该锁只协调本进程，不声明
  防止外部编辑器、其他启动器或同账户恶意进程修改文件；仍须执行文件一致性检查。
- 启动设置需包含本实例可恢复的实际覆盖项（包括 JVM/游戏参数）；不能直接复用当前
  仅导出 Exportable 字段的分享接口，否则会漏参数。不得回滚其他实例/全局账户凭据。
- 设置基线同时保存实例原始覆盖和当时有效值。恢复时，继承值未变则恢复继承；
  全局值已变则仅在该实例固定为基线有效值，不修改全局设置。恢复计划绑定设置 revision，
  由文件恢复事务统一提交；内部设置采集接口不等同于面向用户的分享导出。

## 崩溃与恢复事务

异常退出后，在同一 Service 分析结果中附加 Added/Removed/Changed 差异清单，使用中文
类别与相对路径。没有基线时明确显示原因，禁止出现可点击但无效的回滚按钮。大清单需
可滚动浏览，不在单段消息中截断后假装完整。

差异查询使用 sealed minecraft.instance.recovery.query，以完整实例目录为参数。
只比较基线恢复范围及当前同范围文件；损坏/删除的版本清单也必须能被列为更改，
不能因继承解析失败而完全无法比较。新增的外部版本依赖不自动认领为可删除文件。
启动设置只返回中文名称，不将参数或本机路径值投影到差异列表。差异指纹覆盖基线
revision、所有当前文件内容摘要及设置文档；比较不写入对象或替换基线。

一键回滚绑定完整实例身份、基线 revision 与当前差异指纹。先完整验证/准备恢复文件，
确认实例及共享目录没有活动进程，再应用；已有内容先进入事务备份，失败恢复原状。
需要持久恢复日志，使中断后可继续或撤回；完成前不能删除旧文件的唯一副本。未知或
基线外的数据不删除。回滚完成后刷新版本库、管理页和预检。恢复失败不能遮盖原崩溃报告。

实现顺序：成功事实 → 内容寻址快照与完整性 → 正常退出触发 → 差异分析 → 有日志的
恢复事务 → 崩溃弹窗与管理页入口。每步分别测试，但只有端到端恢复验证后才可标记完成。

回归至少覆盖：正常退出/零码提前退出/取消/失败、不完整采集不替换基线、重复文件不
增加存储、变更/新增/删除差异、共享目录占用、旧差异拒绝、对象损坏、空间/复制故障、
恢复中断重入与回滚、存档保留、参数覆盖恢复、跨根同名实例隔离及 NativeAOT/trim。

## 当前实现边界

已实现内部存储层：SHA-256 内容对象、Brotli 压缩、复用前完整校验与损坏对象修复；
实际读取预算为单文件 512 MiB、事务 8 GiB，边界只额外读取一个字节判断 EOF。
清单最多 10000 项/4 MiB，绑定实例与游戏目录，拒绝路径穿越、重复路径与快照自身。
清单单独临时写入、刷新到磁盘后替换；取消或捕获不完整时保持旧 revision。
对象与清单分别有跨进程文件锁；读取对象只允许写到恢复暂存流，尚未提供修改活文件的 API。

内部文件计划已枚举上述恢复范围及继承依赖，支持按清单 ID 查找改名后的父版本。
提交清单前再次枚举并比较范围；范围变化时保留旧基线。Jvm.Host 观察到正常退出且已确认
游戏窗口后，检查本次崩溃证据并在后台调用恢复服务。复制前后验证实际游戏目录、
实例有效设置及活动进程；必须包含本次启动实际使用的核心文件。前台操作取消采集，
失败/超时/范围不完整时保留旧基线，不能影响游戏退出结果。无窗口确认的平台暂不自动建立基线。
新清单提交后，在持有清单/对象锁时删除不再引用的 .br 对象。清理失败留待下次成功
采集重试；若存在保留给恢复日志的 transactions 目录则暂停清理，不能删除事务引用。
异常中断遗留的 .part 尚不主动删除，避免破坏仍在写入的对象。
崩溃事件携带实际进程的完整实例目录；弹窗先显示分析原因，再通过 sealed query 后台读取
更改清单，每批 12 项，可循环查看全部更改。异步结果绑定弹窗唯一 ID，关闭或替换后不再
更新；不从当前选中实例猜测崩溃归属。分页限制单次排版量，复用滚动消息区。
恢复事务尚未实现，当前不显示无法执行的回滚按钮。
内部设置采集已覆盖全部允许实例覆盖的字段（包括不允许分享导出的参数），并提供绑定
实例身份和设置 revision 的恢复预览。预览检查字段完整性；全局值变化时仅固定本实例
的旧有效值。它尚未接入文件恢复事务或用户按钮，不代表一键回滚已经完成。
失败采集可能留下未引用内容对象，后续成功采集才清理。不能因此声称已满足断电恢复
保证或一键回滚；实际游戏运行与跨平台视觉验收也不能由服务单元测试替代。

## 恢复事务准备协议

准备阶段持有基线清单锁，验证用户看到的基线 revision，再将所有内容对象完整解压到
`transactions/<transaction-id>/`，按 SHA-256 去重。每个暂存对象验证实际长度与摘要，
执行磁盘 flush；全部成功后才原子发布 `prepared.json`。记录绑定实例/游戏目录、基线
revision、文件与摘要映射、设置文档。不存在该记录的目录不得应用到活文件。
准备失败或取消不修改游戏文件，不替换基线；仅清理本次创建的暂存文件。
这个阶段尚不表示已经恢复：后续应用必须再验证当前差异指纹、范围和活动进程，并先
持久化原文件备份与应用日志，协调实例设置提交。仅有 prepared 记录不能作为回滚成功。

准备记录重新打开时须再次校验事务 ID、实例/游戏目录、文件范围及每个暂存对象的实际
长度和 SHA-256。准备记录与对象校验已实现；活文件备份、应用与中断撤回尚未实现。

## 快照与存储页面（新增产品要求）

版本设置新增“快照与存储”选项卡，显示版本文件占用与快照实际存储占用，分别注明
共享游戏目录范围及压缩/去重口径。后台枚举，不在 UI 渲染时执行文件 I/O。
展示所有保留快照的成功运行时间、版本、文件数；最新快照和当前版本比较显示完整
新增/修改/删除清单。支持单项回滚和一键回滚，崩溃分析弹窗共享相同操作。
恢复命令必须绑定实例身份、所选快照 revision、当前差异指纹以及明确条目集合；不能
把 UI 序号作为恢复身份。选择一个条目不能撤销其他条目、全局设置、存档或未知数据。
“保留历史快照”为实例设置，默认关闭；关闭时只保留最新成功快照。开启后保留旧清单，
内容对象仍按摘要复用；对象清理必须保留所有历史清单及未完成事务的引用。关闭后清理
历史的操作须保持最新快照和进行中的事务完整，不能仅删除文件夹然后认为清理成功。
页面、文件大小统计、分页快照列表及最新差异展示已接入。实例设置
`recovery.keep-history` 默认 false，不纳入启动配置快照或恢复，避免恢复动作改变保留策略。
关闭时在下一次成功采集提交新基线后清理历史；失败采集不会清理历史。清理失败保留对象，
下一次成功采集再试。切换实例隔离方式后保留旧快照的原游戏目录身份。
历史按 revision 保存清单并引用共用内容对象；归档旧基线成功后才替换最新清单。读取预算
为 1024 个历史清单、64 MiB 清单总量、100000 条文件记录，超限拒绝继续采集/完整列表，
不静默删除历史。存储统计最多 250000 项/64 层，拒绝链接并标明不完整结果。
逐条/一键恢复命令尚待接入，不以准备层测试或页面展示宣称回滚完成。

## 文件应用日志

每个选中条目携带规范化区域/相对路径、预期当前摘要（不存在为 null）与目标摘要。
目标内容必须属于准备快照；删除仅允许当前恢复范围内的新增项，绝不涉及 saves 等目录。
先逐项验证当前内容并保存原文件到事务目录，所有原内容 flush 后才发布应用日志。
日志在每次活文件变更前记录 attempted 数量，文件通过同目录暂存与原子替换应用。
异常或取消按逆序撤回 attempted 项；只有当前内容仍等于原内容或本事务目标内容时才能
撤回，否则保留日志/备份并报冲突，不能覆盖之后的外部修改。撤回可重复执行。
文件阶段成功只标记 files-applied；它不是完整回滚成功，仍须协调设置提交、进程/操作
互斥与服务入口。事务目录在完整提交或完整撤回前必须保留。

文件应用计划只写一次，进度记录独立保存并引用计划 SHA-256；每项只更新不足 1 KiB 的
进度，避免逐项重写整份计划。当前内部文件事务已覆盖所选文件的应用、原内容备份、
异常补偿、持久记录重新打开后撤回、第三方后续修改冲突及重复撤回。未完成事务的目录
仍保留；启动时自动发现/恢复、完整实例互斥、命令与 UI 按钮尚未接入；内部设置协调见下文。
这些检查不能隔离恶意同账户进程在检查与替换之间持续改写文件，不宣称此处具有更新器
的权限隔离保证。存档和基线外的其他实例依赖不得进入删除计划。

## 恢复互斥

普通安装/导入/改名/删除/模组开关/进程创建共享根目录操作租约；恢复使用独占租约。
恢复等待现有普通操作结束，并取消后台采集。恢复持有租约时，新普通操作等待，不能
通过取消后台采集的机制中断恢复。为兼容安装内部的嵌套改名等操作，有普通操作存续时
仍允许其嵌套租约；计数归零后，等待恢复优先于新普通操作。取消等待者须释放引用并唤醒
其他等待者。此门闩仅覆盖本进程，不替代活动游戏检查或跨进程事务文件锁。

## 设置提交与补偿

恢复设置计划只包含选中字段，保存原始实例 override 与目标 override，并绑定实例与
预览 revision。正向提交使用设置服务的 revision CAS；撤回只恢复原实例 override，
不回滚全局设置或未选字段。撤回检查当前值只能为原值或本事务目标值，第三种值报告冲突。
文件和设置的协调记录先保存设置计划，再应用文件，再记录 settings-applying 意图，
最后提交设置及 committed 标记。失败时先撤回本事务设置，再撤回文件。进度记录必须
保存是否曾尝试提交设置，避免文件阶段失败时误动用户后来修改的设置。记录与备份在
恢复入口和中断恢复完整接入前继续保留，不能将文件阶段成功当成完整恢复成功。

内部协调器已验证文件与设置提交、设置 revision 冲突后的文件补偿、持久 settings-applying 记录重新读取后的补偿与重复恢复。测试为确定性日志重开，并非实际终止进程验收。
